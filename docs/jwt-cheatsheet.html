Good Practices

Verify exp, nbf, iss, aud — not just signature
Short-lived access token + refresh token
Minimal payload (sub, role) — no secrets
Pin allowed algorithms on verify
RS256/JWKS when multiple services verify
httpOnly + Secure + SameSite cookies
Rotate keys via kid; support jti revocation

Bad Practices

Accepting alg:none or unpinned alg (confusion attack)
Secrets/PII stored in JWT payload
No expiration / no refresh flow
Trusting token without calling verify()
Sharing one HMAC secret across untrusted services
Ignoring aud (confused deputy risk)

Decision Rule

  • HS256: same service issues & verifies (monolith / this auth service internally).
  • RS256: other services/gateways must verify without being trusted to issue — private key never leaves the issuer.
