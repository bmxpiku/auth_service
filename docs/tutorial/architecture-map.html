Mapa architektury — auth_service

Fastify 5 + TypeScript (ESM, Node.js ≥ 24). Kliknij dowolny blok, aby rozwinąć szczegóły. Zobacz też: docs/tutorial/ (rozdziały z diagramami Mermaid).
Cykl życia żądania HTTP (uproszczony, przykład POST /users):
1server.ts
listen()
2app.ts
createApp()
3routes/*
AJV validate
4lib/*
logika + Prisma
5errors/*
errorHandler
6reply
JSON response

Start i konfiguracja

🚀 server.ts

src/server.ts

Punkt wejścia procesu Node.js. Ładuje config, tworzy aplikację, nasłuchuje na porcie.

  • loadConfig() zawsze przed createApp()
  • close-with-grace — graceful shutdown na SIGINT/SIGTERM
  • Hook onClose odinstalowuje listenery sygnałów
Zobacz: docs/tutorial/00-przeglad.md

🏭 app.ts

src/app.ts

Fabryka aplikacji Fastify. Używana zarówno przez server.ts, jak i testy (app.inject()).

  • Konfiguruje AJV: removeAdditional: false + ajv-formats
  • setErrorHandler(errorHandler)
  • Ręczna rejestracja tras — brak autoloadingu
  • Hook onClose → closeDb()

⚙️ config/

src/config/{env,configLoader,loggerConfig}.ts

Walidacja zmiennych środowiskowych (Zod) + singleton konfiguracji.

  • loadConfig() — raz, na starcie / w beforeAll testów
  • getConfig() — wewnątrz handlerów, rzuca jeśli nie załadowano
  • Logger wyłączony gdy NODE_ENV=test; redakcja pól wrażliwych
Zobacz: docs/tutorial/02-konfiguracja-i-start.md

Warstwa HTTP

🛣️ routes/

src/routes/{health,users}.ts

Pluginy Fastify — jeden plik na zasób, jawnie rejestrowane w app.ts.

  • export default async function xRoutes(app)
  • Schemat body/response podłączony przez schema: {...}
  • Błędy: throw new XError(...), nigdy ręczny reply.send
Zobacz: docs/tutorial/01-fastify-podstawy.md

📐 schemas/

src/schemas/{health,users}.ts

JSON Schema (json-schema-to-ts) — jedno źródło prawdy dla walidacji runtime i typów TS.

  • as const satisfies JSONSchema
  • FromSchema<typeof schema> → typ TS
  • additionalProperties: false + removeAdditional: false → 400 zamiast cichego strip

Logika i dane

🗄️ lib/db.ts

src/lib/db.ts

Singleton Prisma Client, leniwie inicjalizowany przez PrismaPg adapter.

  • getDb() — nigdy new PrismaClient() bezpośrednio
  • Zależy od getConfig() → wołaj wyłącznie w handlerach
  • closeDb() wołane w hooku onClose
Zobacz: docs/tutorial/04-baza-danych-prisma.md

🧩 lib/prismaErrors.ts

src/lib/prismaErrors.ts

withPrismaError() mapuje kody błędów Prisma na wyjątki domenowe.

  • P2002 (unikalność) → ConflictError (409)
  • P2025 (brak rekordu) → NotFoundError (404)
  • Buduje diagnostics: operation, model, prismaCode, constraint

📧 lib/email.ts

src/lib/email.ts

normalizeEmail() — trim + lowercase przed zapisem/odczytem, dla case-insensitive unikalności.

🔑 lib/jwt.ts

src/lib/jwt.ts

Narzędzia demo do generowania/weryfikacji tokenów RS256 (biblioteka jose). Obecnie nieużywane w trasach.

  • Teoria JWT/JWS/JWE: docs/jwt-manual.md, docs/jwt-cheatsheet.html

Błędy

💥 errors/AppError.ts

src/errors/AppError.ts

Bazowa klasa błędu domenowego: statusCode, code, cause, context.

🏷️ errors/domain/*

src/errors/domain/*.ts

Konkretne podtypy z ustalonym kodem HTTP i machine-readable kodem.

  • ConflictError 409 · NotFoundError 404
  • UnauthorizedError 401 · ForbiddenError 403
  • ValidationError 400 · UnprocessableError 422

🛡️ errors/errorHandler.ts

src/errors/errorHandler.ts

Jedyne miejsce, które loguje i wysyła odpowiedź błędu. Rejestrowane przez setErrorHandler.

  • Błąd walidacji AJV → 400 + details
  • AppError → status/code z instancji, log tylko jeśli cause
  • Inny błąd → log pełny, klientowi generyczne 500
Zobacz: docs/tutorial/03-obsluga-bledow.md, docs/prisma-error-handling.md

prisma/schema.prisma
